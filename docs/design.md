# P식 여행 프론트엔드 디자인 가이드

## 1. 디자인 목적

본 문서는 `P식 여행` 프론트엔드 화면을 일관되게 구현하기 위한 디자인 기준 문서이다.

이 서비스의 핵심 경험은 다음 흐름이다.

```text
사용자 상황 입력 → 추천 코스 확인 → 지도 기반 코스 상세 확인 → 저장/제보/관리
```

따라서 모든 화면은 기능을 많이 보여주는 것보다, 사용자가 현재 해야 할 행동을 명확하게 인지하고 다음 단계로 자연스럽게 이동하도록 설계한다.

---

## 2. 서비스 디자인 방향

### 2.1 핵심 컨셉

> 지금 내 상황에 맞는 여행 코스를 빠르게 추천받는 서비스

사용자는 정확한 목적지를 알고 들어오는 것이 아니라, “지금 어디 가지?”라는 상태로 진입한다.  
따라서 메인 화면은 검색 서비스가 아니라 **상황 입력 기반 추천 시작 화면**으로 설계한다.

### 2.2 디자인 키워드

| 키워드 | 설명 |
|---|---|
| Simple | 한 화면에서 하나의 핵심 행동만 강조한다. |
| Calm | 과한 색상과 장식을 줄이고 여행 정보를 차분하게 보여준다. |
| Card-based | 추천 코스, 장소, 기록은 카드 단위로 표현한다. |
| Map-first | 코스 상세에서는 지도와 동선을 가장 중요하게 보여준다. |
| Trustful | 추천 이유, 거리, 시간, 장소 순서를 명확히 보여준다. |

---

## 3. MVP 화면 범위

초기 MVP에서 구현할 화면은 다음 5개로 제한한다.

| 화면 | 경로 예시 | 목적 |
|---|---|---|
| 메인 검색 화면 | `/` | 여행 조건 입력 및 코스 추천 시작 |
| 추천 코스 목록 | `/courses` | 조건에 맞는 추천 코스 목록 확인 |
| 코스 상세 지도 | `/courses/:courseId` | 지도, 장소 순서, 코스 정보 확인 |
| 장소 제보 | `/places/new` | 사용자가 장소를 제보 |
| 마이페이지 | `/my` | 저장/방문/제보 내역 확인 |

MVP에서는 커뮤니티, 실시간 채팅, 복잡한 리뷰 시스템, 결제 기능은 포함하지 않는다.

## 4. 공통 레이아웃

### 4.1 화면 기본 구조

모든 페이지는 다음 구조를 기본으로 한다.

```text
Header
└── Page Container
    ├── Page Title Area
    ├── Main Content
    └── Optional Bottom Action
Footer 또는 Minimal Footer
```

### 4.2 Header

Header는 전체 페이지에서 동일하게 사용한다.

#### 구성

```text
좌측: P식 여행 로고
중앙 또는 우측: 주요 메뉴
우측 끝: 마이페이지 아이콘 또는 로그인 버튼
```

#### 메뉴

```text
추천받기 / 코스 둘러보기 / 장소 제보 / 마이페이지
```

#### 규칙

- Header 높이: `64px`
- PC에서는 상단 고정하지 않아도 된다.
- 모바일에서는 Header를 단순화하고 메뉴는 햄버거 또는 하단 네비게이션으로 대체 가능하다.
- 현재 페이지 메뉴는 활성 상태로 표시한다.

## 5. 디자인 토큰

프론트엔드에서는 아래 토큰을 기준으로 CSS 변수 또는 Tailwind theme에 매핑한다.

### 5.1 Color

```css
:root {
  --color-bg: #F8F8F8;
  --color-surface: #FFFFFF;
  --color-surface-muted: #F1F2F4;

  --color-text-primary: #1F2933;
  --color-text-secondary: #6B7280;
  --color-text-tertiary: #9CA3AF;

  --color-border: #E5E7EB;
  --color-border-strong: #D1D5DB;

  --color-primary: #111827;
  --color-primary-hover: #374151;
  --color-primary-text: #FFFFFF;

  --color-danger: #DC2626;
  --color-success: #16A34A;
  --color-warning: #D97706;
}
```

#### 사용 원칙

- 기본 배경은 밝은 회색(`#F8F8F8`)을 사용한다.
- 카드, 입력 영역, 모달은 흰색 surface를 사용한다.
- CTA 버튼은 검정 계열 primary를 사용한다.
- 강조 색상은 남발하지 않는다.
- 추천 코스의 무드 태그는 연한 회색 배경 + 짙은 회색 텍스트를 기본으로 한다.

---

### 5.2 Typography

```css
:root {
  --font-family-base: Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;

  --font-size-xs: 12px;
  --font-size-sm: 14px;
  --font-size-md: 16px;
  --font-size-lg: 20px;
  --font-size-xl: 28px;
  --font-size-2xl: 36px;

  --line-height-tight: 1.25;
  --line-height-base: 1.5;
  --line-height-loose: 1.7;
}
```

#### 사용 기준

| 용도 | 크기 | 굵기 |
|---|---:|---:|
| 메인 히어로 제목 | 36px | 700 |
| 페이지 제목 | 28px | 700 |
| 섹션 제목 | 20px | 600 |
| 카드 제목 | 16px | 600 |
| 본문 | 14~16px | 400 |
| 보조 설명 | 12~14px | 400 |

#### 문장 톤

- 버튼: 동사형으로 작성한다.
  - 예: `코스 추천받기`, `이 코스 저장하기`, `장소 제보하기`
- 안내문: 사용자가 얻는 결과를 먼저 말한다.
  - 예: `현재 위치와 기분을 바탕으로 바로 갈 수 있는 코스를 추천해드려요.`
- 오류문: 원인과 다음 행동을 함께 제공한다.
  - 예: `현재 위치를 가져오지 못했어요. 지역을 직접 입력해주세요.`

---

### 5.3 Spacing

```css
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 20px;
  --space-6: 24px;
  --space-8: 32px;
  --space-10: 40px;
  --space-12: 48px;
}
```

#### 사용 기준

- 카드 내부 padding: `20px` 또는 `24px`
- 섹션 간격: `32px`
- 폼 필드 간격: `16px`
- 페이지 상단 여백: `40px`
- 버튼과 설명문 간격: `12px`

---

### 5.4 Radius / Shadow

```css
:root {
  --radius-sm: 6px;
  --radius-md: 10px;
  --radius-lg: 16px;
  --radius-xl: 24px;

  --shadow-card: 0 1px 3px rgba(15, 23, 42, 0.08);
  --shadow-floating: 0 8px 24px rgba(15, 23, 42, 0.12);
}
```

#### 사용 기준

- 입력창: `radius-md`
- 카드: `radius-lg`
- 지도 패널 / 바텀시트: `radius-xl`
- 기본 카드는 강한 그림자를 사용하지 않는다.

## 6. 공통 컴포넌트 규칙

### 6.1 Button

#### 종류

| 타입 | 사용 위치 | 스타일 |
|---|---|---|
| Primary | 핵심 CTA | 검정 배경, 흰색 텍스트 |
| Secondary | 보조 행동 | 흰색 배경, 회색 border |
| Ghost | 부가 행동 | 배경 없음, 텍스트 중심 |
| Danger | 삭제/취소 | 빨간색 텍스트 또는 border |

#### 크기

```text
Large: 48px height / 메인 CTA
Medium: 40px height / 일반 버튼
Small: 32px height / 카드 내부 버튼
```

#### 규칙

- 한 화면의 Primary 버튼은 최대 1개만 둔다.
- 카드 내부에서는 Secondary 또는 Ghost 버튼을 우선 사용한다.
- 비활성 버튼은 opacity만 낮추지 말고 클릭 불가 상태를 명확히 한다.

---

### 6.2 Input / Select

#### 기본 구조

```text
Label
Input Box
Helper Text 또는 Error Text
```

#### 규칙

- Label은 항상 표시한다.
- Placeholder만으로 입력 의미를 설명하지 않는다.
- 오류가 발생하면 필드 하단에 구체적인 메시지를 표시한다.
- 검색형 입력은 좌측에 돋보기 아이콘을 사용할 수 있다.

#### 예시

```text
현재 위치
[ 내 위치 사용하기 ] 또는 [ 지역명을 입력하세요 ]

이동 가능 시간
[ 1시간 이내 ▼ ]
```

---

### 6.3 Tag / Chip

여행 분위기, 코스 성격, 이동 수단 등을 표현할 때 사용한다.

#### 예시

```text
#산책 #카페 #감성 #혼자 #도보
```

#### 규칙

- 선택 가능한 태그는 Chip Button으로 구현한다.
- 선택된 상태는 border와 배경을 함께 변경한다.
- 한 줄에 너무 많은 태그를 노출하지 않는다.
- 코스 카드에서는 최대 3개까지만 보여주고 나머지는 `+N`으로 처리한다.

---

### 6.4 Card

서비스 내 대부분의 정보는 카드 단위로 보여준다.

#### 기본 구조

```text
Thumbnail 또는 Icon
Title
Meta Info
Description 또는 Route Summary
Tags
Action Area
```

#### 규칙

- 카드 전체 클릭과 내부 버튼 클릭의 역할을 명확히 분리한다.
- 리스트 카드에서는 상세 진입을 가장 자연스러운 행동으로 둔다.
- 찜/저장 버튼은 카드 우측 상단 또는 우측 하단에 고정한다.

---

### 6.5 Empty State

데이터가 없을 때 빈 화면만 보여주지 않는다.

#### 예시

```text
아직 저장한 코스가 없어요.
마음에 드는 코스를 저장하면 여기에서 다시 볼 수 있어요.
[추천 코스 보러가기]
```

---

### 6.6 Loading State

추천 코스 생성, 지도 로딩, 마이페이지 데이터 조회 시 사용한다.

#### 규칙

- 전체 페이지 로딩보다는 영역별 skeleton을 우선 사용한다.
- 추천 코스 생성은 1~2초 이상 걸릴 수 있으므로 문구를 보여준다.

```text
지금 상황에 맞는 코스를 찾고 있어요.
```

## 7. 화면별 디자인 가이드

## 7.1 메인 검색 화면 `/`

### 목적

사용자가 자신의 상황을 입력하고 코스 추천을 시작한다.

### 핵심 사용자 행동

```text
여행 조건 입력 → 코스 추천받기
```

### 화면 구성

```text
Header
Hero Section
└── Title
└── Subtitle
Search Condition Card
└── 현재 위치
└── 원하는 분위기
└── 이동 가능 시간
└── 선택 사항: 동행 유형
Primary CTA
```

### 권장 문구

```text
지금, 어디로 떠나볼까요?
현재 위치와 기분에 맞춰 바로 갈 수 있는 코스를 추천해드려요.
```

### 입력 필드

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| 현재 위치 | 필수 | 내 위치 사용 또는 지역 직접 입력 |
| 원하는 분위기 | 필수 | 산책, 맛집, 카페, 자연, 조용함 등 |
| 이동 가능 시간 | 필수 | 1시간, 2시간, 반나절, 하루 |
| 동행 유형 | 선택 | 혼자, 친구, 연인, 가족 |

### MVP 기준 입력 축소안

초기 구현에서는 아래 3개만 필수로 둔다.

```text
현재 위치 / 원하는 분위기 / 이동 가능 시간
```

### UI 규칙

- 입력 영역은 하나의 큰 카드로 묶는다.
- CTA 버튼은 카드 하단 전체 너비로 배치한다.
- Hero 이미지는 실제 이미지가 없어도 placeholder 또는 단순 일러스트로 처리 가능하다.
- 추천 시작 전에는 복잡한 정보를 보여주지 않는다.

## 7.2 추천 코스 목록 `/courses`

### 목적

조건에 맞는 추천 코스를 비교하고 하나를 선택한다.

### 핵심 사용자 행동

```text
추천 코스 확인 → 상세 보기
```

### 화면 구성

```text
Header
Page Title
Applied Filter Summary
Course List
└── Course Card
Filter Button
```

### Course Card 구조

```text
[썸네일]
코스명
한 줄 설명
장소 순서 요약
소요 시간 · 거리 · 이동 방식
태그 2~3개
[상세 보기] [저장]
```

### 카드 예시

```text
한강 산책 & 감성카페 코스
여의나루역 → 한강공원 → 카페 → 전망 포인트
약 2시간 · 3.2km · 도보 중심
#산책 #카페 #감성
[상세 보기] [♡]
```

### 필터

MVP에서는 복잡한 필터 사이드바를 만들지 않는다.

초기 필터는 버튼 하나로 처리한다.

```text
[필터]
```

클릭 시 모달 또는 드롭다운으로 다음 항목만 제공한다.

```text
소요 시간 / 이동 방식 / 분위기
```

### UI 규칙

- 추천 결과 수를 상단에 표시한다.
- 조건 변경은 현재 페이지에서 가능하게 하되, 복잡하면 메인으로 돌아가도 된다.
- 카드 리스트는 PC에서 1열 또는 2열까지 허용한다.
- 모바일에서는 무조건 1열 카드 리스트를 사용한다.

---

## 7.3 코스 상세 지도 `/courses/:courseId`

### 목적

사용자가 추천 코스의 동선과 장소 정보를 확인하고 저장하거나 길찾기를 시작한다.

### 핵심 사용자 행동

```text
지도 확인 → 장소 순서 확인 → 저장 또는 길찾기
```

### 화면 구성

```text
Header
Course Summary
└── 코스명
└── 소요 시간 / 거리 / 이동 방식
Main Layout
├── Map Area
└── Place Sequence Panel
Bottom Info
└── 추천 이유
└── 유의사항
Primary Action
└── 이 코스 저장하기 또는 길찾기 열기
```

### PC 레이아웃

```text
좌측 또는 중앙: 지도
우측: 장소 순서 패널
```

### Mobile 레이아웃

```text
상단: 코스 요약
중앙: 지도
하단: 장소 순서 바텀시트
```

### 장소 순서 패널

```text
1. 여의나루역
   출발 지점 · 지하철역

2. 한강공원 산책로
   도보 12분 · 산책

3. 감성 카페
   도보 8분 · 휴식

4. 전망 포인트
   도보 10분 · 사진 명소
```

### 지도 규칙

- 지도 마커에는 순서 번호를 표시한다.
- 코스 경로는 선으로 연결한다.
- 현재 선택한 장소는 마커와 리스트 양쪽에서 강조한다.
- 지도 라이브러리의 기본 컨트롤은 과하게 노출하지 않는다.

### CTA 우선순위

1. `길찾기 열기`
2. `이 코스 저장하기`
3. `공유하기`

MVP에서는 공유하기를 제외해도 된다.

## 7.4 장소 제보 `/places/new`

### 목적

사용자가 추천 데이터에 활용할 장소를 제보한다.

### 핵심 사용자 행동

```text
장소 정보 입력 → 제보 완료
```

### 화면 구성

```text
Header
Page Title
Place Report Form
└── 장소명
└── 위치
└── 방문 날짜
└── 추천 분위기
└── 사진 업로드
└── 한 줄 설명
└── 태그
Submit Button
```

### 필드 규칙

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| 장소명 | 필수 | 검색 또는 직접 입력 |
| 위치 | 필수 | 주소 또는 지도 선택 |
| 방문 날짜 | 선택 | 사용자가 방문한 날짜 |
| 추천 분위기 | 필수 | 산책, 맛집, 카페 등 |
| 사진 | 선택 | MVP에서는 선택으로 둔다 |
| 한 줄 설명 | 필수 | 100자 이내 |
| 태그 | 선택 | 최대 5개 |

### UI 규칙

- 제보 화면은 메인 플로우보다 보조 기능으로 취급한다.
- 입력 폼은 2컬럼보다 1컬럼을 우선한다.
- 제출 전 미리보기는 MVP에서 제외한다.
- 제출 완료 후 `/my?tab=reported` 또는 완료 화면으로 이동한다.

## 7.5 마이페이지 `/my`

### 목적

사용자가 추천받은 코스, 저장한 장소, 방문 기록, 제보 내역을 확인한다.

### 명칭 원칙

일반 사용자에게는 `대시보드`보다 `내 여행`이라는 표현을 우선 사용한다.

### 화면 구성

```text
Header
My Page Layout
├── Profile Summary
├── Activity Summary Cards
├── Recent Saved Courses
└── Recent Reported Places
```

### 메뉴

```text
내 여행
추천받은 코스
저장한 코스
저장한 장소
다녀온 코스
제보한 장소
설정
```

### 요약 카드

```text
추천받은 코스 12
저장한 장소 8
방문한 코스 23
제보한 장소 120
```

### UI 규칙

- 숫자 요약 카드는 상단에 4개 이하로 제한한다.
- 최근 항목은 최대 5개만 표시한다.
- 전체 목록은 `더보기`로 이동한다.
- Empty State를 반드시 제공한다.

## 8. 반응형 기준

### Breakpoints

```css
:root {
  --breakpoint-mobile: 0px;
  --breakpoint-tablet: 768px;
  --breakpoint-desktop: 1024px;
  --breakpoint-wide: 1280px;
}
```

### Desktop

- 최대 컨테이너 너비: `1120px`
- 추천 리스트: 1~2열
- 상세 지도: 지도 + 우측 패널
- 마이페이지: 좌측 메뉴 + 우측 콘텐츠

### Tablet

- 최대 컨테이너 너비: `720px`
- 추천 리스트: 1열
- 상세 지도: 지도 상단 + 장소 리스트 하단

### Mobile

- 좌우 여백: `16px`
- Header 단순화
- 추천 카드 1열
- 지도 상세는 바텀시트 구조
- 하단 고정 CTA 사용 가능

## 10. 접근성 기준

- 모든 버튼은 키보드로 접근 가능해야 한다.
- 아이콘 버튼에는 `aria-label`을 제공한다.
- 지도 마커는 리스트에서도 동일 정보를 확인할 수 있어야 한다.
- 색상만으로 선택 상태를 구분하지 않는다.
- 텍스트 대비는 일반 본문 기준 WCAG AA 수준을 목표로 한다.
- 폼 오류 메시지는 해당 입력 필드와 연결한다.

## 12. 금지 규칙

- 한 화면에 Primary 버튼을 여러 개 두지 않는다.
- 추천 코스 카드에 너무 많은 설명을 넣지 않는다.
- 지도 상세 화면에서 지도보다 부가 정보를 더 크게 보여주지 않는다.
- 장소 제보를 메인 추천 흐름보다 앞세우지 않는다.
- MVP 단계에서 리뷰, 댓글, 팔로우, 랭킹 기능을 추가하지 않는다.
- 색상을 많이 사용해 카테고리를 구분하지 않는다.
- Placeholder만으로 입력 의미를 설명하지 않는다.

## 15. 최종 기준

프론트엔드 구현 시 각 화면은 다음 질문에 답할 수 있어야 한다.

1. 사용자가 이 화면에서 무엇을 해야 하는가?
2. 다음 행동 버튼이 명확한가?
3. 추천 코스의 시간, 거리, 장소 순서가 바로 이해되는가?
4. 지도와 리스트 정보가 서로 연결되어 보이는가?
5. 데이터가 없거나 오류가 나도 사용자가 다음 행동을 할 수 있는가?

이 기준을 만족하지 못하는 UI는 기능이 구현되어 있어도 완료로 보지 않는다.
